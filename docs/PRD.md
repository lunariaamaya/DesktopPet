## 1. 背景、结论与文档约定

做一款 Windows 动态壁纸与桌面角色结合的陪伴产品：角色生活在一个场景中，能回应触碰、参与简单环境互动，与用户文字交流，记住用户明确允许保存的信息，并执行少量受控电脑操作。长期核心是情感陪伴，效率功能用于辅助日常生活，不以全面替代鼠标键盘为首版承诺。

用户已确认：MVP 固定角色与固定场景；角色、场景根据用户后续上传的参考图片制作；必须包含角色互动、场景互动、文字对话、个人记忆、基础电脑操作；后续增加登录、多场景、角色与服装定制、剧情剧本；功能模块分离并通过接口组合；默认中文，预留英语、西班牙语、日语。

沿用此前约束：目标为两天可体验原型、七天公开测试版本。工期从素材和模型访问方式满足开工条件后计算，具体以技术验证为准。

标记规则：

- **已确认**：上述用户明确要求。
- **建议默认**：本文为推进设计选择的方案，非用户已批准事项。
- **待确认**：需产品负责人决定或由技术验证确定，不阻塞本次文档交付。
- **发布阻断**：该项未满足时不能宣称公开版达标，不等同于 PRD 无法编写。

本 PRD 参考 product-definition-prd 的定位、用户任务、范围、IA、契约、状态、验收、指标、交接框架。针对桌面产品调整：不套用工具站 Hero、SEO 批量页面、域名验证、CPC/KD、默认英文或强制三档定价；用桌面界面矩阵、安装激活漏斗、留存与陪伴价值验证替代。未做新的关键词研究、市场规模估算或当前价格调查，不编造相应数据。

## 2. 市场假设、替代方案与证据

### 2.1 要验证的假设

1. 场景中的持续角色存在，比独立聊天框更能促成用户主动再次交流。
2. 可控、可纠正的个人记忆能增强熟悉感，并且不会让用户感到被监视。
3. 少量真实电脑任务能增加日常接触，但不会稀释陪伴定位。
4. 用户愿意为角色、服装、场景、剧情的个性化内容付费。以上均为待验证假设。

### 2.2 四层替代方案

| 层次 | 方案 | 已有依据/边界 | 本产品验证方向 |
|---|---|---|---|
| 直接 | VPet 与其模组/插件 | 前序讨论已检索 README：桌宠互动、模组、插件及 WPF 核心；未在本机运行 | 场景、记忆和真实任务能否形成连贯陪伴 |
| 间接 | 动态壁纸产品、AI 聊天产品、养成游戏 | 产品类别参考，未完成逐项竞品实测与定价比较 | 用户是否愿意将分开的体验合在一起 |
| 手动 | 壁纸＋聊天窗口＋自行操作电脑 | 工作流假设，需访谈确认 | 降低唤起和切换成本 |
| 不作为 | 静态桌面、不需要持续陪伴 | 需求可能不足，需负面反馈验证 | 是否有足够主动回访，而非首次新奇 |

参考：[VPet README](https://github.com/LorisYounger/VPet/blob/main/README.md)、[英文说明及素材授权](https://github.com/LorisYounger/VPet/blob/main/README_en.md)。仅用于既有研究溯源；源码复用、插件兼容、素材授权须在实际采用前复核。未确认的功能不得写成竞品不支持。

## 3. 用户与定位

### 3.1 ICP（假设画像，不伪装成访谈结论）

| 用户 | 场景与痛点 | 关注价值 | 付费意愿状态 |
|---|---|---|---|
| **主 ICP：成年 Windows 长时间桌面用户，喜欢虚拟角色陪伴** | 学习或工作间隙想轻松交流，普通聊天窗口缺少存在感 | 好看、不打扰、记得住、能回应 | 待访谈与真实购买验证 |
| 次 ICP：桌面美化与原创角色爱好者 | 希望桌面体现个人审美与角色归属 | 外观、场景、内容可组合 | 待验证，MVP 不提供定制购买 |
| 后续 ICP：角色/剧情创作者 | 希望交付可互动内容 | 素材规范、预览、分发工具 | 待验证，首版不开放投稿 |

MVP 建议面向成年人公开测试，不将未成年人作为首批目标。目标地区暂按中文用户设计，具体可分发地区和服务可用性在发布前确认。

### 3.2 JTBD 与成功标准

| ID | 用户任务 | 可观察的成功 |
|---|---|---|
| J01 | 工作间隙看见角色，触碰一下获得回应 | 点击后立即有动画/文本反馈，桌面仍可正常操作 |
| J02 | 与角色聊今天的事 | 能连续交流；角色设定一致；错误时可恢复 |
| J03 | 让角色记住称呼或喜好 | 用户确认后保存，重启后可使用；能查看、更正和忘记 |
| J04 | 简单改变场景氛围 | 点击场景热点触发可见变化，状态重启后保留 |
| J05 | 让角色打开应用或找到文件 | 告知实际结果，不把失败说成成功；用户能取消 |
| J06 | 专心工作时不被打扰 | 一键暂停/勿扰；不抢焦点，壁纸被遮挡时降低开销 |

### 3.3 定位六步

1. 替代：桌宠、动态壁纸、聊天工具、手动组合及不使用。
2. 候选属性：场景存在、可管理记忆、即时互动、受控小任务的一体体验。属于待验证差异，非宣称独有。
3. 用户价值：熟悉感、低门槛交流、可控制的陪伴和少量实际帮助。
4. 最佳用户：主 ICP，愿意持续与一个固定角色建立熟悉感。
5. 品类：桌面陪伴应用，从固定场景的轻量体验切入。
6. 时机假设：模型与角色渲染可以组合出原型，但真实留存和成本仍需验证。

定位语句：为需要轻度日常陪伴的 Windows 用户，提供一个住在动态桌面里的虚拟伙伴，通过场景互动、文字交流与可管理记忆形成连续体验，并辅助完成少量电脑任务。

消息层级：主标题「桌面里，住着一个愿意听你说话的伙伴」；副标题说明固定场景、文字交流和经允许保存偏好；利益点为可回应、记得住、可随时安静；证据仅使用真实录屏与测试记录；入口用「开始聊天」「查看它记住的事」。不编造用户评价。

禁用承诺：真正拥有意识、保证治愈孤独、医疗或心理治疗、完全替代人际关系、任何电脑任务都能完成、无限免费云端服务、绝对隐私或永不出错。

## 4. MVP 范围与版本边界

### 4.1 P0：首版全部必须交付

| 需求 ID | 功能模块 | MVP 范围 |
|---|---|---|
| F01 | 桌面宿主 | 真正挂载桌面层；托盘、快捷唤起、暂停、正常退出与壁纸恢复；单主屏 |
| F02 | 角色表现 | 固定角色；待机、注视/点击反馈、思考、说话、结果反馈；动作能力可查询 |
| F03 | 角色互动 | 至少两种不同热点互动（如头部、身体），冷却与打断规则 |
| F04 | 场景互动 | 固定场景；至少两个可见热点；建议灯光开关与窗外氛围切换，最终映射依参考图确定 |
| F05 | 文字对话 | 中文多轮、流式或渐进显示、取消、重试、复制；固定人格；新建会话 |
| F06 | 个人记忆 | 手动或对话明确提议保存；确认、召回、查看、编辑、删除、全部清除与导出 |
| F07 | 电脑操作 | 已配置应用打开、允许域名网页打开、授权目录文件查找；结果和权限可见 |
| F08 | 设置与本地资料 | 本地资料 ID；模型连接、权限、快捷键、勿扰、减少动态效果、数据管理 |
| F09 | 内容加载 | 固定内容包也按 manifest 加载；缺少可选动作时降级；不写死资源到业务逻辑 |
| F10 | 国际化基础 | zh-CN 完整；en/es/ja 接口预留；伪本地化测试，不宣称已支持翻译 |
| F11 | 可用性与交付 | 安装/解压运行、重复启动处理、错误日志脱敏、基本诊断和发布说明 |

### 4.3 首版 NOT-DO

不做账号登录/云同步/支付/商城/第三方插件执行；不做任意图片自动绑定、自由换装、多角色、多场景选择、复杂走动和物理交互；不做语音与常驻麦克风；不做截图监视、键盘记录、通用 GUI 自动点击、任意命令执行；不做文件写入/移动/删除、自动发消息、支付操作；不支持 macOS/Linux、跨屏场景和多显示器交互；不以好感度数值、签到压力或付费情感惩罚推动使用。

## 5. 用户流程与交互规则

### 5.1 首次启动

安装/启动 → 明确 AI 与联网边界 → 展示默认固定场景和角色 → 选择体验示例或设置模型连接 → 完成一次互动/聊天 → 按需授予电脑工具权限。离线、未配置模型时，场景和互动仍可用；聊天显示明确设置入口。电脑权限和可选分析采集默认关闭。开机自启默认关闭。

### 5.2 桌面与角色（F01–F04）

- 角色与场景位于桌面层，不永久覆盖用户应用。聊天、设置、任务面板为独立可唤起窗口，默认不置顶、不抢焦点。
- 桌面图标、任务栏、右键菜单保持可用。角色/场景点击通过明确的「互动模式」开启；默认桌面浏览模式不吞掉桌面操作。托盘/快捷键和面板均可切换，提供退出互动模式提示。
- 热点采用设计坐标和缩放映射，窗口缩放后位置仍正确。背景适配优先保留角色与热点，必要时留边，不任意裁掉交互对象。
- 点击反馈在本地完成，不依赖模型；每个热点默认 1 秒冷却，连续点击不积压动作。设置「减少动态效果」后以静态表情或文字替代。
- 动作优先级：用户暂停 > 用户直接互动 > 对话/任务表现 > 场景自动表现 > 待机。高优先级打断采用过渡/回到待机，不叠加冲突动作。
- 场景至少一项持续轻动画；灯光等状态由 Scene 模块保存。角色可响应场景事件，但无需复杂位移。关闭互动音效不影响文字聊天。
- 托盘提供打开聊天、互动模式、暂停动画、勿扰、设置、退出。快捷键建议 Ctrl+Alt+Space，可更改；冲突时给出设置入口。
- Explorer 重启、休眠恢复、显示设置变化后尝试重挂载；失败进入可关闭预览窗口并提示。预览是故障降级，不能冒充真正动态壁纸达标。

### 5.3 文字对话（F05）

- 中文输入法组合期间不发送；Enter 发送，Shift+Enter 换行；空白不能提交；输入上限建议 2,000 字符。
- 单会话同一时刻一条请求，发送按钮转为停止；正在执行工具时另显示任务停止入口。取消后保留已显示文字并标注中断，不把半截消息记为完整事实。
- 暂定每次上下文包含固定人格、最近最多 20 条消息及最多 10 条相关有效记忆，并受模型上下文/字节预算二次裁剪。历史全部显示与发送给模型的范围区分。
- 模型无权限决定宿主设置；角色表情只能输出经过校验的有限标签。无合法动作时回退，不影响聊天。
- 网络失败保留草稿，给出可重试错误；对话网络请求默认 30 秒无内容超时、单轮总时限 90 秒。重试是新请求，不能重复执行已经完成的电脑操作。
- 新会话不等于清除长期记忆；界面分别提供「新会话」「删除本会话」「清除记忆」。删除本会话清除对应正文，不自动抹除用户已单独确认的记忆，并在删除前说明。

### 5.4 记忆（F06）

- 短期上下文是当前对话；长期记忆是用户确认的事实，不将模型总结、虚构剧情、推测情绪默认为事实。
- 示例：「请记住我喜欢下雨天」→ 显示候选内容「你喜欢下雨天」→ 用户确认 → 保存成功 → 之后对话可召回。用户也能在记忆面板直接新增。
- 每条记录展示内容、来源类型、创建/更新时间；关联本地资料与角色关系。MVP 只保存称呼、喜好、交流习惯，不鼓励保存凭证、财务或医疗等敏感资料。
- 更正同类偏好时提示替换或保留，不静默覆盖；删除/修改增加 memoryRevision，并取消携带旧记忆的在途回复。下一请求使用新版本，避免旧回答重新写回。
- 记忆关闭后不召回、不创建候选；已有记录保留至用户删除。候选不进入检索；候选过期七天自动清除。
- 默认本地持久化：聊天保留 30 天可设为不保存，删除过期记录发生在启动和每日清理；确认的记忆保留至用户删除；本地诊断保留七天。导出为带版本 JSON，告知包含私人信息；首版不做导入。
- 「全部清除」二次确认并取消在途请求，清除聊天、候选与记忆；偏好设置和 API 凭证提供独立清除选项。说明无法撤回已发给外部模型的数据或用户自行导出的副本。

### 5.5 基础电脑操作（F07）

首版只做有明确结果的本地工具，不做屏幕识别与自由鼠标代理。

| 工具 | 输入与行为 | 权限与结果 |
|---|---|---|
| app.open | 用户选择的 appId，无模型生成命令行参数；启动已登记可执行文件/快捷方式 | 首次配置由用户选定；权限有效且本次明确指令时可直接执行；结果区分进程启动与应用完成加载 |
| web.open | 标准化后的 HTTPS URL | 域名首次确认，可记住域名授权；拒绝其他协议、凭证 URL、localhost 与私网目标；反馈「已交给默认浏览器」，不宣称页面加载成功 |
| file.find | 用户授予的 rootId、文件名/扩展名，不读取内容 | 默认不递归；可显式选择子目录，跳过重解析点和隐藏系统目录；上限 100 条/10 秒；部分结果标明截断 |

- 文件查找结果只在本地面板展示；模型接收数量、完成状态等摘要，不接收完整路径与文件内容。首版不自动打开结果文件，用户可手动复制路径。
- 不明确的目标先追问，如「打开那个」；不支持的行为直接说明边界并提供手动建议。
- 执行入口展示计划和权限；未授权显示「允许一次/记住此项授权/拒绝」。一次授权绑定工具、标准化参数摘要、本地资料及本次请求，不可复用到新参数。
- 已有权限不等于可在闲聊中自行操作。每个任务必须有当前用户的明确操作意图；聊天中的引用、角色台词和场景点击不作为系统操作授权。
- 单个请求最多 3 个工具步骤；串行执行；不允许模型自行循环。单一用户请求最多一个活动任务，重复提交使用 requestId 去重。
- 停止是尽力取消尚未发生的动作与搜索；已经启动的应用或浏览器不会自动关闭，不能显示为已撤销。
- 授权可在设置撤销；策略模块在执行前再次检查参数和权限。权限判断由执行器负责，模型输出不能绕过。

### 5.6 陪伴行为边界

- 固定人格应温和、尊重选择；不通过指责离开、制造独占关系或威胁遗忘促使付费或回访。首版不主动推送情绪话题，不分析屏幕判断用户情绪。
- 不声称是真人、医疗专业人士或能保证改善心理状态。危险请求走内容策略；普通负面情绪允许自然交流，不把所有情绪都改成机械警告。
- 勿扰禁止主动气泡和互动音效，保留用户主动唤起；未来剧情角色的行为也须服从用户暂停与勿扰。

## 7. 模块化与技术约束

详细接口以 [architecture-contracts.md](./architecture-contracts.md) 为准。

- 一个模块承担一个清晰功能，不等同于一个按钮、一个进程或一项微服务。MVP 使用模块化单体＋必要的本地执行边界。
- UI 不直接读写数据库或调用 OS；通过应用层调用模块接口。角色不直接持有模型密钥，内容包不含可执行脚本，模型不直接拥有系统权限。
- 模块可拆分为：DesktopHost、Character、Scene、Interaction、Conversation、Memory、Task、Permission、Settings、Profile、Content、Locale、Storage、Diagnostics；未来独立接入 Auth、Sync、Wardrobe、Story、Entitlement、Voice。
- MVP 只实现必须模块；未来模块定义端口和数据归属，无需创建空实现充数。跨模块使用命令取得结果、事件通知状态；关键写入不依赖无人确认的广播。
- 引擎、模型供应商、持久化适配器可替换；接口稳定不代表未来永不迁移。新增字段、能力与资源版本必须有兼容和迁移策略。
- VPet 复用与独立渲染二选一由 D1 技术验证决定。最多半天验证，不将其与 WPF、Electron 或游戏引擎中的任何一种实现写成已验证事实。

## 8. 国际化需求（F10）

- 支持标识：zh-CN 默认已实现；en、es、ja 为预留语言。MVP 设置只展示可用语言，不展示空翻译。
- UI、错误、任务模板、角色固定台词、场景名称和隐私说明均用资源键＋命名参数，禁止拼接句子；日期、数字、排序用 locale 格式化；首版不要求 RTL。
- 回退：请求语言 → 内容包声明的默认语言 → zh-CN → 开发环境显示 missing-key，生产显示安全通用文本并记录 key。所有中文必需键缺失阻断发布。
- UI 语言、对话语言、内容台词语言为独立字段；未来改变 UI 语言不翻译用户原始记忆，也不重置角色关系。
- 对话接口始终携带 locale；工具返回 errorCode 和结构化数据，由客户端本地化。剧情分支、物件和动作使用稳定 ID，不能用中文文本当主键。
- 预留长文本和西语扩张、日语断行、字体回退；伪本地化模拟 40% 文本增长，无按钮截断和关键内容遮挡。新语言上线前逐项校对真实翻译。

## 9. 数据、隐私与模型连接

建议默认：本地优先、无需登录、用户自填 API Key（BYOK）的公开测试版。此项待产品负责人确认；BYOK 会提高门槛，但避免七天内同时开发公共付费网关。若改为提供方承担调用费，网关、配额和防滥用成为新增 P0，必须重新评估排期。

- 告知用户哪些聊天与选中的记忆会发送给其配置的模型服务；本地存储不等于全程离线。
- 凭证用 OS 凭证存储或等价保护，仅执行/主进程可取；日志、导出、前端状态不返回密钥。不将供应商的共享密钥放入安装包。
- 自定义模型地址由用户在设置中明确填写并测试，默认仅允许 HTTPS；本地模型例外需单独开启，仅连回环地址且说明行为。与网页打开工具的策略分离。
- 模型能力适配器声明 stream/tools/cancel 支持。模型不支持工具调用时保留聊天，明确该连接无法使用自然语言电脑任务；公开版至少验证一个支持完整 P0 的连接配置。
- 后续本地模型是核心能力，不要求用户用云端账号才能启用。ModelProvider 统一封装云端和本地推理；Ollama 优先走原生接口，不能仅将云端 baseURL 替换为本地地址就宣称完成接入。MVP 交付配置与接口契约，完整接入验收在后续版本执行。
- 模型配置区分 provider、部署位置、协议、地址、modelId、凭证引用、超时及能力。能力按实际服务与所选模型确定，不将 Ollama 的能力当作每个模型都具备的能力。
- 本地模式默认回环地址，例如 http://127.0.0.1:11434；局域网/公网地址不在默认授权内。切换模型需取消在途请求并处理上下文预算变化，保留用户原始历史与记忆。模型未安装、服务未启动、资源不足均明确反馈。
- 本地推理故障不自动回退云端；发送历史/记忆到云端需用户另行明确选择。连接本地地址不代表必然离线：未来须验证模型确实在本机运行，而非通过本地服务转用云模型。默认不由本应用下载模型、启动后台服务或开放网络监听。
- 聊天正文、记忆正文、路径、URL 查询参数、凭证均不得进入分析埋点。诊断导出预览脱敏字段，崩溃转储不默认上传。
- 文件扫描只限明确授权根目录，不扫描整盘、不读取文件正文，不把结果路径自动发送给模型。
- 删除清除应用活动数据及由应用管理的备份；用户导出、系统备份、供应商留存不在本机删除能力内，界面明确说明。卸载提供保留/清除本地数据选择，若安装器无法提供则给出清除入口和目录说明。

## 10. 性能、可靠性与支持边界

下列为设计目标，需 D1 在参考设备上建立基线并记录 CPU/GPU/内存/OS；不是已测结果。

| 项目 | 发布验收目标 |
|---|---|
| 平台 | 建议 Windows 11 x64，单主显示器；具体受测版本写入 release notes；Windows 10 等未测环境不宣称支持 |
| 首次显示 | 排除安装与首次资源解压后，本地场景 5 秒内显示 |
| 本地互动 | 点击到反馈 P95 ≤ 200ms，至少 30 次测量 |
| 渲染 | 默认上限 30 FPS，可降为 15/静态；不依赖模型维持动画 |
| 资源 | 参考机可见待机 5 分钟平均 CPU ≤ 5%、GPU ≤ 10%、内存 ≤ 500MB；CPU 按系统总量口径，GPU 按实际渲染引擎记录 |
| 后台节能 | 完全遮挡/最小化/会话锁定时停止连续动画，保留必要消息处理；电池模式降帧；10 分钟无持续资源爬升 |
| 恢复 | Explorer 重启、休眠、断网、服务超时均有恢复或明确降级，不遗留不可关闭窗口 |
| 稳定性 | 连续运行至少 2 小时无崩溃；20 次启动退出无阻断；正常退出恢复原桌面显示 |
| 取消 | 按停止后 1 秒内呈现已取消/正在终止状态；无法撤销的已执行动作明确标注 |
| 持久化 | 已确认记忆重启后保留；异常退出不损坏已有库；写入失败不能假成功 |

不要求模型首字速度固定达标；记录实际 P50/P95 和供应商配置，前端必须即时展示等待、超时与取消。性能不达标优先降帧/简化效果，不删掉必需功能后仍宣称通过。

## 11. 商业模式与增长验证

MVP 建议免费公开测试、不接支付。未来候选为角色/场景/服装/剧情内容包与 AI 服务订阅，二者权益分开；换装不重置关系，取消订阅不删除本地记忆。确切价格、税费、退款、渠道分成和市场意愿尚未验证。

成本模型输入：每活跃用户月成本 = 模型输入/输出 token 成本＋记忆整理调用＋语音（未来）＋存储/流量＋内容摊销＋服务支持。定价前测真实调用量、重度用户分位数和获客成本，不承诺无限云端使用。

首周分发建议：可下载安装包、真实演示录屏、已知问题、反馈模板；先邀请少量成年测试用户，再公开发布。本文不授权实际发布、发帖、联系第三方或收款。

官网/SEO 不进入本轮开发：未来提供下载、使用场景、帮助、版本记录、隐私/许可页面；不机械套用 1+4+N 工具页。搜索量、KD、CPC、域名与广告预算留待专门获客验证。

## 12. 指标与复盘

北极星候选：每周有至少两天主动进行有效交流或互动的用户数。有效交流定义为一轮用户输入获得完成回复；纯待机、误触、自动动作不计。不是“在线越久越好”。

最小漏斗：下载（渠道可得时）→ 首次启动 → 首次互动 → 连接成功 → 首次完成聊天 → 保存/召回记忆 → D1/D7 回访。任务完成是辅助指标，不能替代陪伴留存。

本地记录事件，默认不联网上传；分析上传须单独 opt-in，拒绝不影响功能。无同意不计算其远端行为数据；报表注明样本偏差。事件只包含匿名安装 ID、sessionId、appVersion、locale、相对/UTC 时间、功能 ID、枚举状态、耗时分桶、受控 errorCode。

| 事件 | 触发 | 允许附加字段 |
|---|---|---|
| app_started / onboarding_completed | 启动/完成引导 | 版本、连接模式 |
| character_interacted / scene_interacted | 用户触发成功反馈 | hotspotId、actionId |
| conversation_completed / conversation_failed | 完整结束/失败 | turnId、耗时、错误码；不含正文 |
| memory_saved / recalled / deleted | 已提交保存/确实装入上下文/已删除 | 操作类型、数量；不含记忆文本 |
| task_requested / permission_decided / task_finished | 请求/权限决定/任务终态 | toolId、结果枚举、耗时；不含路径/URL |
| data_exported / app_error | 导出成功/受控错误 | 数据类别、errorCode |

未来才增加 login_success、content_equipped、story_completed、purchase_verified 等事件，购买成功必须由服务器校验。

复盘目标为内部试验阈值，非行业基准：

| 时间 | 样本与目标 | 决策 |
|---|---|---|
| 发布后 D7 | ≥10 位实际测试者；脚本化核心流程通过率 ≥90%；无已知数据丢失/越权 | 不满足则停止扩大分发，优先修复；样本不足先补招募 |
| D14 | ≥20 位可观察且同意的激活用户；D7 留存候选 ≥25%；访谈至少5人理解重复使用原因 | 达标继续优化；低于目标分析场景/对话价值，不能仅加服装 |
| D30 | ≥30 位可观察激活用户；≥5人每周多日主动使用；至少3人对具体付费内容表达可核实意愿 | 达标可扩大内容实验；意愿不等于付费验证；连续两轮无主动回访考虑缩小或转向 |

D7 留存分母为完成首次聊天且已有满七天观察窗口的用户，分子为第七个本地自然日主动完成互动/聊天的用户；记录安装时区用于归属。小样本同时报告人数，不只报百分比。
