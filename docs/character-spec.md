## 1. 已确认的外观基线

| 项目 | 要求 |
|---|---|
| 总体 | 小女孩形象，娇小可爱；保留参考图身体比例，不擅自改为大头 Q 版或成人比例 |
| 头发 | 白色、微卷；三方向长度一致，以正面自然最低发束接近手腕的长度为最新要求，取代早期笼统的及腰描述 |
| 双眼 | **角色自身左眼红色，右眼蓝色**。正面图中观者右侧为红瞳、左侧为蓝瞳，禁止靠水平镜像生成另一视图 |
| 耳朵 | 精灵耳是真实角色耳部；头顶猫耳是另外佩戴的发饰，二者不得混成一对耳朵 |
| 猫耳发饰 | 头部固定佩戴，左右耳各自可动，摆动不能导致发饰漂离头部 |
| 颈饰 | 绿宝石项链，独立配饰；不擅自替换为领结或其他宝石 |
| 上衣 | 白色露肩婚纱式上衣，童话卡通表现；不增加透视材质或夸张身体细节 |
| 下装 | 白色七分长裙，覆盖大腿及大部分小腿；脚踝、白色脚环和脚部必须露出 |
| 背面 | 无额外指定花纹，沿用正面材质与装饰语言；结构合理收口，不凭空增加拖尾、大蝴蝶结或翅膀 |
| 尾巴 | 佩戴式猫尾装饰，与身体分离并独立摆动；最新挂点为臀部上缘近骶骨的背中线位置，固定结构藏于裙装；不因挂点下移改变配饰分类 |
| 足部 | 光脚，小而纤细、低足背和薄脚掌；圆润脚趾末端但不婴儿肥；白色脚环独立存在，不替换成鞋袜 |

文字明确细节优先于低清图片的模糊像素；图片决定比例、整体轮廓和风格。无法辨认的裙边、珠宝切面等允许设计稿中做最小补全，标注为推定，并在三视图冻结前由用户看图确认。

## 2. 部件和绑定组织

采用用户给出的八类外观分区，同时保留底层统一身体与骨架。分区不等于把身体在每条边界处机械切断；可见接缝、蒙皮连续性和换装遮挡规则须在建模时处理。

| 稳定槽位 ID | 分区 | 制作与驱动要求 |
|---|---|---|
| hair | 头发 | 分发束组织，预留独立摆动骨骼/控制；脸部轮廓不被发丝永久遮住 |
| headwear | 帽子/头饰 | 猫耳配饰，跟随头部；两耳各有局部动作控制 |
| face | 脸部 | 异瞳、精灵耳、眨眼、视线、嘴型和表情；不假设所有内容都是独立可拆网格 |
| chest_accessory | 胸部配饰 | 项链挂点；此槽位是配饰类别，不是将躯干作为服装拆卖 |
| upper | 上衣 | 与身体共用骨架，肩臂活动测试；可与当前裙装保持视觉连续 |
| lower | 下装 | 七分裙，分段裙摆控制；坐下、跨步、旋转时验证变形与覆盖 |
| waist | 腰部 | 尾巴与佩戴部件，独立尾链；可有主动动作和受限的跟随摆动 |
| feet | 鞋子/脚部 | 本角色光脚；脚环独立配饰随脚踝移动，未来可换鞋但首版不穿鞋 |

基础身体、主骨架、手指与脚趾不属于可随意删除的槽位。身份 ID 与外观包 ID 分离；换发型/衣服不能重置记忆。分离网格不要求每件物品独立绘制调用，性能优化时可合批，但不能丢失编辑结构。

主骨架须覆盖躯干、头、四肢、手指（比耶需要独立食指/中指姿态）、脚部；附加控制包括眼睛/脸部、发束、双猫耳、尾链与裙摆。耳饰/尾巴主动动画与次级摆动需有权重和开关，避免同一骨骼被两个系统同时争抢。待机次级摆动不能破坏坐地和旋转等动作。

具体骨骼数、面数、纹理分辨率、格式与渲染器尚未冻结；先用一个绑定样机检查动态桌面性能再确定预算。建议保留可编辑源工程，运行时交换格式由引擎验证决定，不用只有一个不可编辑导出文件作为全部交付。

## 3. 设计稿与三视图交付

顺序：参考整理 → 统一全身设计稿 → 用户看图校正 → 正/侧/背三视图＋细节图 → 三维静态模型 → 骨骼/表情绑定 → 代表性动作验证 → 扩充动作库。

现有参考已足够启动，不必须另做氛围插画。三视图是建模参考，不是三维模型；图像生成工具不直接产出拓扑、骨架与动画。

三视图要求：

- 同比例、同头高、同地面线、同服装、同中性表情；正交或近似正交，避免透视夸张。
- 正面、固定一侧的 90° 侧面、背面；侧面朝向标注清楚，不能在不同图中改变耳饰/尾巴安装位置。
- 自然站姿、手臂略离躯干，服装结构可读；另出 A-pose 绑定参考仅在建模阶段需要时制作。
- 头发自然垂下的正式视图之外，另给背部局部结构图或隐藏头发说明图，展示上衣背部、腰部尾巴根部和裙腰，不凭头发遮挡省略设计。
- 补充脸部（异瞳与精灵耳）、猫耳安装、项链、裙摆、尾巴根部与脚环特写。
- 保留适龄卡通造型；服装不透明，动作时有合理遮挡，不用身体夸张来表现婚纱风格。
- 色彩尽量中性光照，区分白发/白衣/白裙层次；不把游戏光环、昵称、UI、粒子效果画进角色纹理。

通过标准：三个方向轮廓相互解释得通；正背裙长相同；脚踝和脚环可见；异瞳方向正确；猫耳、尾巴和精灵耳归属准确。生成稿常见的多余肢体、配饰增减、发型变更或三视图不一致必须修订。

## 4. 完整动作需求与建议排期

用户已明确要求：待机、转头、说话、点击回应、走路、坐下、跳舞、摔倒、比耶、芭蕾转圈，后续尽量丰富。本节完整登记，不将未实现动作说成已有能力。

建议拆分交付层次，排期待模型/绑定样机验证；该建议不代表用户同意删减：

| actionId | 需求 | 动画验收重点 |
|---|---|---|
| idle | 待机/呼吸/眨眼 | 循环接缝、视线、发束/尾巴轻摆 |
| look | 左右转头、视线跟随 | 保持异瞳方向；限制头颈范围 |
| talk | 说话 | 脸部嘴型，不只有全身晃动；文字版可简化节奏但不声称语音口型同步 |
| react.head / react.body | 两种点击回应 | 可辨别、可打断、能回到待机 |
| walk | 走路及起停 | 选择原地步态或带位移；由宿主决定位置，避免 root motion 重复位移 |
| sit.enter / sit.idle / sit.exit | 坐下、坐姿、起身 | 座椅高度/地面坐姿需单独适配，裙摆不严重穿腿 |
| dance | 一段舞蹈 | 确定独立片段与是否循环，不能把整段游戏画面贴在角色上 |
| fall / fall.recover | 摔倒与起身 | 碰地、裙摆与长发、恢复；采用安全卡通表现，无伤害细节 |
| peace | 比耶 | 食指/中指明确，其他手指自然；不以整手贴图冒充任意角度手势 |
| ballet.spin | 芭蕾转圈 | 旋转轴、脚部接地、裙摆/发尾跟随；是否专业足尖动作由设计稿确定 |

对七天 MVP 的建议：优先完成 idle/look/talk/react，其他动作在三维绑定验收后扩展。若要求上述全动作随七天首版一起交付，这是对原 PRD 的显著范围增加，需要重新估算，不能承诺原工期自动成立。

每条动画应声明 duration、loop、interruptible、rootMotion、entryPose、exitPose 和所需能力；只能播放已声明动作，不能从文本捏造动画存在。坐姿、摔倒等需状态过渡；暂停与停止优先于表演。

## 5. 视频分析记录（初步）

实测元信息：960×600，60 fps，28.000 秒，1,680 帧。开头可见游戏菜单，角色占画面较小，昵称、光环和粒子会遮挡轮廓。

已完成：全段以 2 fps 抽样，生成 56 帧概览；角色区域裁剪为 x=350,y=270,w=200,h=220，辅助放大仅便于观察，不代表增加了细节；对 5.000–7.000 秒的 120 个原始连续帧逐格对照。未宣称完整精查全部 1,680 帧。抽样时间有取帧偏差，下列仅是粗分段，不是最终动作切片点。

| 大致时段 | 可见内容 | 可信度与用途 |
|---|---|---|
| 约 0–3 秒 | 正/侧向重心切换、手臂摆动、步态式小位移 | 可作姿态与节奏参考，不能据此还原完整三维步态 |
| 约 3–7 秒 | 前倾/抬腿、伸臂、转向与重心变化；伴随特效 | 5–7 秒已密集检查，观察到多组姿势停留及切换；60fps 容器不等于60个不同姿势/秒 |
| 约 8–12 秒 | 身体降低到地面、侧卧/蜷曲样姿态，随后恢复站姿 | 可参考摔倒/恢复的构图与形态；精确落地帧和起身时序仍需加密检查 |
| 约 12–22 秒 | 站姿、抬臂、转向、倾身与再次接近地面 | 可辨粗动作，不确认精确手指或专业芭蕾技术 |

比耶的手指和完整芭蕾动作无法由当前像素明确验证，作为用户新增动作独立设计，不能标为从视频准确复刻。背面、隐藏肢体与深度结构不可从这个单镜头精确恢复。
