# 二维角色生产管线与验证方案

日期：2026-11-07。二维路线与以下生产顺序已由用户确认；具体渲染工具、素体比例、阈值和自动化合格率仍待验证。本文件是当前角色制作路线的上位补充，覆盖旧文档中必须先完成三维建模的要求。旧三视图、GLB、试修和视频保留作历史资料。

2026-11-09 更新：用户提供 `素体参考图/魔法师/` 8 张、`素体参考图/弓箭手/` 9 张；A 暂名魔法师，B 暂名弓箭手。已完成逐图查看与索引。参考条件生成被图像服务拒绝，现仅有不使用参考图输入的独立机械人台草案，尚无人形素体定稿或二维绑定；见 [本轮制作记录](base-template-study-2026-11-09.md)。

## 1. 已确认的范围

生产顺序：**上传图片 → 整理角色外观 → 分层与补图 → 二维绑定及动作制作 → 自动检查与预览**。

- 恰好两个基础身体模板，稳定 ID 为 `base-a`、`base-b`；未经用户变更不增加第三类。A 暂名魔法师，B 暂名弓箭手；两类参考均已于 2026-11-09 提供，尚未交付经用户批准的素体。不得将生成候选的比例或体型称为用户已确认。
- 素体是无发型、无服装/饰品的中性美术基底，简化身体结构，不绘制私密解剖细节。基础脸型、耳型是否属于模板或可替换部件，在基准图审阅时确认。角色人格、身份、记忆独立于身体模板。
- MVP 仍为固定角色、固定场景。两模板体系是内容规范，不把用户自助上传生成、换装商城、自由捏脸提前纳入 MVP。未来定制优先在模板范围内实现。
- 场景使用分层二维素材；日常角色动作采用分层变形，坐下、睡眠、转身等大姿态可使用专用姿势/动作素材。不能用站姿强行拉成全部姿态。三视图继续作为外观参考，不再是三维交接的必经步骤；需要背面动作时补相应二维素材。

## 2. 参考图能恢复到什么程度

参考图可测量可见轮廓、头身关系、眼线、肩肘腕、膝踝等地标，但服装遮挡、姿态与透视使隐藏结构无法唯一恢复。输出是有依据、可校正的标准素体重建设计，不能称为精确提取真实原始素体。

每个模板独立收集参考、统一尺度，优先正面全身，其次清晰侧面/背面和局部；多图应保持同一比例体系，不将不同画风直接平均。用户无需提供专业参数；图像不足时先标未知，不填造数字。

交付：带参考叠图的中性站姿、测量地标、头高归一化的比例表、侧面/背面必要结构推定、已见/推定/用户确认三类依据。禁止在一次推定后将比例伪装成已获用户认可。

| 参数类别 | 示例 | 记录原则 |
|---|---|---|
| 整体 | 身高/头高、头宽、躯干及腿长 | 使用相对比例，不从无尺标图片捏造厘米身高 |
| 肢体 | 肩宽、上臂/前臂、大腿/小腿、手足尺寸 | 区分可见点、遮挡估计点、姿态投影差异 |
| 脸部 | 眼线/眼距、脸型、耳位 | 区分模板几何与角色可替换外观 |
| 工程 | 画布、原点、关节锚点、图层顺序 | 模板内统一，A/B 分别建立，不承诺动作跨模板直接复用 |

用户通过看图确认比例后再冻结 `templateRevision`。衣服和发型适配冻结版本；比例改动应触发兼容性复验，不能只换 ID 继续宣称兼容。

## 3. 五阶段输入输出

| 阶段 | 输出及检查 | 闸门 |
|---|---|---|
| 上传图片 | 原件、来源、角色/模板关联；去除 UI/特效的辅助参考不覆盖原件 | 可辨角色；原件留存；无法判断的模板不自动强配 |
| 整理外观 | 模板拟合候选、比例地标、色板、装饰槽位、推定项 | 首次模板及角色外观经用户看图确认 |
| 分层与补图 | 同画布/原点的透明 PNG 层、可编辑分层源文件；补齐被遮住的肢体/发束/衣物边缘 | 静态重组与批准设计一致；暴露区域无缺口、白边和重复部件 |
| 二维绑定及动作 | 头脸/视线/嘴/躯干/手臂等控制；发饰/尾饰独立层；专用坐姿及过渡 | 动作、打断、姿态入口/出口及服装兼容均有声明 |
| 自动检查与预览 | 文件/参数/贴图/兼容校验，采样图、MP4/GIF、可点击预览器、失败项与重试版本 | 自动检查与美术人工审阅分别记录；未通过不标生产可用 |

分层至少覆盖前/后头发、脸、左右眉眼及高光、嘴部、躯干、左右上/前臂及手、左右腿脚、服装、各配饰与遮挡蒙版。八个外观槽位继续沿用：hair/headwear/face/chest_accessory/upper/lower/waist/feet；槽位不是实际绘图层数，头发必须分前后等更细层。

自动 QA 可以检查文件、alpha、画布/锚点、缺层、参数范围、动作回退、透明裂缝候选和静态差异；不能单凭“未发现错误”证明美观、完全无粘连、隐藏身体正确或全部动作自然。

## 4. 工具结论与接口边界

推荐优先验证 Live2D Cubism Editor 制作与 Cubism SDK 内嵌运行，尚未采购、安装、连接或确认制作自动化合格率。Live2D 是品牌/格式体系；Spine 是另一种二维骨骼工具，并非兼容 Cubism 的编辑器。VTube Studio 是运行/跟踪/预览工具，不能代替分层和模型制作，也不作为产品必须依赖的宿主。

- 官方 [Cubism 外部集成 API](https://docs.live2d.com/cubism-editor-manual/external-application-integration-api/)：WebSocket/JSON，可读写已有模型参数；应按 [官方命令表](https://docs.live2d.com/cubism-editor-manual/external-application-integration-api-list/) 验证实际 Editor 版本支持哪些操作，不能推断有通用全自动建模 API。
- 社区 [CubismExternalEditMCP](https://github.com/nana7chi/CubismExternalEditMCP/blob/master/i18n/README_EN.md)：README 区分基础参数读写和依赖 5.4 Alpha 的扩展编辑，并注明 Alpha 有效期至 2026-09-14，已早于本次核查日期。故仅列为实验候选，不宣称当前可直接部署或已验证完整绑定。来源为仓库说明，非 Live2D 官方兼容承诺。
- [VTube Studio 官方 API](https://github.com/DenchiSoft/VTubeStudio)：可用于已制作模型的控制/预览，属于 API 接入候选，不等同于本会话已连接的 MCP。
- [Cubism SDK](https://www.live2d.com/en/sdk/about/) 用于产品内渲染，业务层通过 Character 端口访问，不直接依赖编辑器/MCP。
- [SDK 发布许可](https://www.live2d.com/en/sdk/license/) 对 Expandable Applications 有单独审核/协议要求。未来用户导入/生成角色可能涉及该类别，此为用途匹配推断，需向官方核实；不能因小团队就默认适用豁免。开发验证可以先进行，不把未确定商业条件当已获许可。

本会话没有已连接的 Cubism/VTube/Spine 工具。本轮只调研与修订规格，没有安装 MCP 或软件。后续先以实际 Editor 版本跑通“读参数→改参数→恢复→预览”的小测试，再决定是否依赖它做结构编辑。界面自动化可作为辅助，不能据此保证制作完全无人介入。

## 5. 验证样机与通过条件（待执行）

先做 A 类一位角色、一个二维场景；A 可用后再引入 B 做模板隔离/换装复验。官方示例模型可测 SDK 连通，不能替代本角色外观和分层验收。原生 Cubism 绑定与自制分层播放原型须明确区分。

样机窗口包含：重置、待机、说话、摸头、摸脸、坐下、起身、开/关灯、暂停、切装测试及问题截图。先用独立预览窗口验证素材，最后验证真实桌面挂载；录屏或视频只是辅助证据，不能替代互动样机。

| 闸门 | 如何操作 | 通过条件 |
|---|---|---|
| G0 外观与素体 | 原设计/中性基准/重组图并排，地标叠图，用户选择认可或标记差异 | 比例、脸型、配色、关键饰品不出现用户不可接受的变化；遮挡推定项清楚。地标误差阈值须在基准图批准后冻结，不预先杜撰还原度百分比 |
| G1 日常动作 | 待机 60 秒，触发说话、有限左右注视、头发和尾饰摆动；导出正面及局部录屏 | 无明显断层、白边、肢体被衣服/头发牵走；眼睛左右/颜色正确；嘴部确有动作；循环无明显跳接 |
| G2 点击与过渡 | 摸头/摸脸各重复 20 次，动作中切换/暂停；站→坐→站连续 10 次 | 两热点反馈不同；无动作队列堆积；能回待机；坐姿使用适配素材，衣服无明显粘连或穿插。需要专用动作的换装不得冒充通用兼容 |
| G3 场景与宿主 | 灯光热点改变场景及角色状态；100/150/200% 缩放；切换互动模式、切应用和退出 | 热点跟随缩放；角色/场景互不误触；默认不吞图标操作、不抢焦点；暂停与退出可用。普通预览窗通过不等于桌面挂载通过 |
| G4 可编辑与换装 | 单独改一个发饰/颜色参数，替换一件兼容衣物，重开源工程；A/B 后续分别检查 | 用户用参数/素材替换完成一项简单修改，无需动网格；更改不破坏其他部件；错误模板/绑定版本服装明确拒绝；身份与记忆不重置 |
| G5 性能与可复现 | 记录机器、版本、分辨率、内存、CPU/GPU、帧率，前后台运行；在另一配置打开交付包 | 按 PRD 目标评估，不先声称二维必然低开销；没有开发机绝对路径依赖。艺术 QA、桌面 QA 与完整 P0 发布 QA 独立记录 |

样机通过只确认这位角色、这些动作和已测服装。两个模板都通过之前不承诺两类通用换装，更不承诺任意上传图片都能自动通过。项目七天目标需在分层、制作与工具接口验证后重估，不能把三维停工等同于二维已准备就绪。

## 6. 模块化与版本

维持既有 Character/Scene/Interaction/Conversation/Memory/Task/Wardrobe 等边界。新增 CharacterCreation 为未来创作任务编排端口，BaseTemplate 为恰好两套基础规范；AI 工具只提交有限语义动作，不直接操纵编辑器或 OS。

素材兼容至少检查 baseTemplateId、templateRevision、rigProfileVersion、poseSetVersion、槽位、支持动作和遮挡层。共用基础模板可减少适配工作，不能让一张服装图自动适配站姿、坐姿和背面动作。有限捏脸须声明参数范围和影响的兼容版本；不得无意形成第三种未批准的比例模板。

源图、推定、用户批准、分层、工程、运行时包、QA 与预览分开版本管理。每次更新提交/推送 GitHub；大文件沿现有资产规则通过产物版本和哈希追溯。原三维模型归历史，不覆盖删除。通用 character-reference-to-turnaround skill 仍用于外观参考整理，历史案例不自动改写成二维绑定完成记录。
