# 角色素材到角色设计稿与三视图 SOP

版本：1.0 · 日期：2026-11-03。范围止于二维美术冻结与三维交接，不承诺自动产出生产级三维模型。既包含下次可执行的流程，也保留本次实际版本与失败经验。

复用入口：[character-reference-to-turnaround skill](../skills/character-reference-to-turnaround/SKILL.md)。完整操作与提示词骨架见 [制作流程](../skills/character-reference-to-turnaround/references/workflow.md)，新角色直接复制 [工作簿模板](../skills/character-reference-to-turnaround/assets/character-workbook.md)。三者分别承担入口、操作细节和填写记录，避免维护多套重复规则。

## 1. 流程、产物与验收关口

| 阶段 | 实际工作 | 产物 | 进入下一阶段的条件 |
|---|---|---|---|
| 素材入库 | 查看原图，分离 UI/特效；视频抽样和重点连续帧检查 | 素材索引、可见信息与局限 | 能说明依据与未知项 |
| 设定整理 | 对齐比例、角色左右、服饰结构、配饰归属、可动项 | 外观基线及疑问清单 | 影响身份的歧义已确认 |
| 设计候选 | 从素材统一轮廓与美术风格，最小补全隐藏细节 | 全身设计及必要局部 | 用户认可设计方向；问题已登记 |
| 三视图 | 同尺度、站姿、地面线，统一前侧背结构 | 正/侧/背候选 | 三方向可相互解释 |
| 局部修订 | 唯一底图 + 单轮变更单，逐项处理视角与遮挡 | 新候选、parent、提示词/掩模 | 本项通过，已认可部分无明显漂移 |
| 颜色与降噪 | 分材质取样、保边处理、连续曲线、选区验证 | 色板、处理脚本参数与 QA | 颜色连续，噪声改善，没有范围外变化（如有此承诺） |
| 暂定冻结/冻结 | 记录用户结论、原图哈希、未解决项 | 可复现交接包 | 用户明确认可，不替用户判定 |

“先插画、再设计稿、再三视图”是本次可用的路径；已有清晰设计稿时可跳过重复插画。三视图的作用是约束三维造型，不代表二维图片本身已具备真实的三维结构。

## 2. 本次素材与确认信息

输入为用户提供的 16 张角色 PNG、一段 `跳舞视频.avi` 及文字描述。原始素材保存在本地 `角色素材/`，未作为公开资产自动推送。权利来源记录为用户声明原创并拥有完整权利，不作独立权属鉴定。

视频实际为 960×600、60fps、28 秒、1,680 帧；全段以 2fps 抽取 56 帧概览，另检查 5–7 秒的 120 个连续原始帧。没有精查全部 1,680 帧，也没有自动动作捕捉。游戏 UI、粒子和小尺寸角色限制了手指及背面结构判读。详见 [角色规格的视频记录](character-spec.md#5-视频分析记录初步)。

这次锁定的身份特征：保留原比例与纤细四肢；白色微卷长发；角色自身左眼红、右眼蓝；精灵耳与佩戴式猫耳分开；绿宝石颈饰；白色露肩上衣和七分长裙；佩戴式尾巴；光脚及白色脚环。角色与场景模块化需求只约束后续制作，不意味着出图时已完成分网格、绑定或换装。

## 4. 本次最重要的经验

| 失败或歧义 | 原因/证据 | 下次的具体处理 |
|---|---|---|
| 圆润变成四肢变粗 | 把末端形状与整体围度混为一个变量 | 分别锁定围度、指趾钝圆、脚长和脚背角度 |
| 小花位置错误 | “后耳”未区分猫耳发饰与精灵耳 | 用对象 + 挂点 + 对应视图描述 |
| 侧面蝴蝶结像正面 | 配饰被复用而未遵循投影 | 对照固定点、方向、近远面和遮挡 |
| 后视发束跑到身前 | 忽略层次关系 | 用前侧图推导后视遮挡；只改位置，不重做发质 |
| 后视手指重复正面 | 虎口/拇指仍在近侧 | 局部放大，定义近侧小指、紧邻四指、远侧拇指；最终依实际手势验证 |
| 多轮越改越差 | 一轮涉及太多变量，整图生成漂移 | 一轮一项或紧密相关小批次，失败退回已认可底图 |
| “冷白皮”被理解成灰白 | 色名没有指定取样部位与色值 | 记录参考小腿受光区，约 #FEEEEA，描述为低饱和浅粉象牙白 |
| 配色正确却显黑 | 旧灰影未提亮 | 分开处理色相/饱和度/明度，不通过加色掩盖暗沉 |
| 降噪只凭肉眼或生成提示词 | 生成式处理仍可能添加纹理 | 同 ROI 前后对比，保边处理并检查实际噪声指标 |
| 硬颜色阈值产生碎斑 | 阈值两侧变换不连续 | 连续曲线 + 平滑权重场，检查掩模边缘 |
| “其他不变”只是提示词 | 生成工具没有像素范围保证 | 对严格保持任务用授权的掩模/回贴/确定性处理，并验证范围外像素 |

## 5. 后处理复用边界

本项目可复现脚本：[降噪与肤色](../scripts/denoise-character.ps1)、[配色匹配与白色提亮](../scripts/match-character-colors.ps1)。它们的材质位置与阈值针对本次 1536×1024 布局，不能直接套在任意新角色上。新角色应重做选区与样本，不能只换输入文件名。

通用 skill 附带的 [art_qa.py](../skills/character-reference-to-turnaround/scripts/art_qa.py) 只做取样和修改范围检查，不自动修改图片。依赖 Python、Pillow、NumPy；不改变全局 Python 环境。示例 ROI 仅适用于当前图：

```powershell
python skills/character-reference-to-turnaround/scripts/art_qa.py sample assets/characters/first-character/concepts/turnaround-v02.png --roi 732,840,7,36 --output tmp/reference-calf-report.json
```

本次程序化处理已获用户明确授权；该授权不自动扩展到其他用户、其他工具、外部上传或费用。

## 6. 三维交接与质量边界

本次程序化三维草模虽可打开、旋转和导出，但用户明确否定其美术质量。文件结构和渲染检查不能替代与二维角色的相似度验收，不继续将草模标作可用角色成品。

用户现已改用 Tripo 生成模型，反馈其结果较好；我们尚未检查该外部模型文件。后续应沿用用户选择，先验收其模型，再评估分件、拓扑、绑定、裙摆与头发动作。不要以新的程序化草模替代用户要求的外部模型路线。接入核查见 [Tripo 接入说明](tripo-integration.md)。
