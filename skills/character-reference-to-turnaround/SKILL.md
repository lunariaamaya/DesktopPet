# 角色素材 → 设计稿 → 三视图

交付相互一致、可追溯、由用户确认的角色图；先保住已认可的身份、比例与造型，再解决当前指定的问题。用户仅要求修订现有图时，从修订阶段开始，不强制重走完整流程。

## 开始前

- 读取现有角色规格、用户最新反馈和已认可版本；建立一份明确的当前基线。日期最新不等于已获认可。
- 实际查看参考图片；对视频标明元信息、抽样范围和遮挡，不能把抽样说成完整逐帧分析。
- 将信息分为用户明确、图片可见、推定待确认。追问会改变造型的缺失信息，能独立完成的素材整理继续执行。
- 首次完整制作读 [制作流程](references/workflow.md)；仅局部修改读其中“修订与回退”“颜色与降噪”“验收”部分。
- 可复制 [角色工作簿](assets/character-workbook.md) 到项目中，填写规格、版本关系和当前变更单。不要把上一位角色的配色、服装或手势带入新角色。

## 制作顺序与关口

1. 整理素材索引和外观基线，明确角色左右、身体比例、附属物归属、隐藏结构与未来可动部件。
2. 生成设计候选，集中确认整体风格、轮廓、比例和材质；未确认的候选不升级为三视图依据。已有合格设计无需重复生成插画。
3. 以已认可设计生成正、侧、背视图：统一尺度、站姿、地面线与主要高度。同一角色从三个方向观察，不复制粘贴正面配饰，也不靠镜像制造侧背视图。
4. 建立待修问题清单，优先修复视角、遮挡、装饰结构等一致性问题；按可验收的小批次修订。每轮写清底图、特征参考、修改区域及保持项。
5. 造型获认可后再处理色彩连续性、局部配色和降噪；若用户本轮只要求颜色，就只处理颜色，不擅自补改旧问题。
6. 用户确认后冻结图片、SHA256、色板、左右约定、部件说明与未解决项，再移交三维工具。没有确认就标记候选，不能替用户宣布定稿。

生成或生成式编辑位图时，使用环境已有的图像工具，并遵守其适用 skill。记录完整提示词、输入图角色和输出文件。不用脚本绘图伪装为生成结果。精确后处理走用户已授权的方法；工具要求的授权边界继续适用。

## 修订中的关键约束

- 用户指定“只改这里”时，上一认可图是唯一底图；其他版本仅作指定特征参考。被否定版本不能因某个局部好看而整体复活。
- 提示词里的“其他不变”不保证生成式编辑逐像素一致。需要严格保持时，采用授权的局部掩模、裁剪回贴或确定性变换，并检查接缝、光色和选区外变化。
- 圆润末端、手足整体围度、脚长、脚踝角度是不同变量。不要将“圆润”解释为肢体增粗，或只拉长脚尖代替整体脚型调整。
- 手指近远顺序由真实手势和观察方向决定；同一手势的前后图不能只复用同一虎口和指缝。用局部放大验证，必要时先确认手势结构草图。
- 毛发位置、长度、颜色、蓬松程度分别记录；修改遮挡关系不意味着重新设计发型。
- 一轮失败后回到上一认可版，缩小范围或换方法；同一问题连续两次无有效改善时先诊断，不继续盲目整图生成。

## 验证与留档

对比完整图和问题局部，同时检查正常显示与低对比度下的斑块、底噪、过暗白材质。色名仅作沟通，附参考部位、RGB/HEX和明暗层级；采样不要落在轮廓、腮红、投影或抗锯齿边缘。

有 Python、Pillow 和 NumPy 时，可使用 [art_qa.py](scripts/art_qa.py)：

```text
python art_qa.py sample IMAGE --roi x,y,width,height --output REPORT.json
python art_qa.py compare BEFORE AFTER --editable-mask MASK --output REPORT.json
```

掩模白色表示允许变化，黑色表示应保持；灰色按非零视为允许变化，不能拿扩大后的掩模隐藏越界。工具检查尺寸、像素变化、alpha与采样统计，不证明解剖结构、造型一致或全图无噪声；人工看图与用户验收仍是必需步骤。报告默认不覆盖。

每版另存图片与记录，记录 parent、参考特征、方法/参数、验证、用户状态。交付当前候选或冻结版本、可点击文件与尚存限制；Git 提交/推送按项目约定执行，不因调用此 skill 自动获得外部发布授权。

三维阶段单独验证真实网格、贴图、结构分件、绑定与动作。三视图不是这些能力的证明；程序化草模和“看似三维”的渲染也不能替代相似度验收。
